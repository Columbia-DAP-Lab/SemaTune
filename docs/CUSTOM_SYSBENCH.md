# Defining a custom Sysbench workload

Start from a checked configuration and change only the workload and schedule
fields. This compact example defines Fixed OLTP read/write with two 10,000-row
tables, 16 threads, and a 5,000 transaction/s cap:

```json
{
  "benchmark": "sysbench_oltp",
  "tuner_type": "fixed",
  "parameter_ranges": {
    "min_granularity_ns": [100000, 100000000],
    "latency_ns": [100000, 100000000],
    "cstate_max": ["POLL", "C6", "C3", "C1E", "C1"],
    "napi_busy_poll": [0, 1000],
    "wakeup_granularity_ns": [100000, 100000000],
    "migration_cost_ns": [100000, 100000000],
    "max_perf_pct": [0, 100],
    "min_perf_pct": [0, 100]
  },
  "parameters_to_tune": [
    "min_granularity_ns", "latency_ns", "cstate_max", "napi_busy_poll",
    "wakeup_granularity_ns", "migration_cost_ns", "max_perf_pct",
    "min_perf_pct"
  ],
  "fixed_parameters": {},
  "optimization_metric": "latency_p99",
  "optimization_goal": "minimize",
  "max_iterations": 2,
  "post_tuning_windows": 1,
  "window_duration": 10,
  "respect_config_window_duration": true,
  "tuning_mode": "in-window",
  "continuous_apply": false,
  "pin_to_cores": "0-9",
  "bind_network_irqs": false,
  "sysbench_threads": 16,
  "sysbench_tables": 2,
  "sysbench_table_size": 10000,
  "sysbench_rate": 5000,
  "use_perf_stat": true,
  "results_dir": "results/custom_sysbench_fixed"
}
```

Save it as `custom_sysbench.json`, then validate it without executing:

```bash
PYTHONPATH=src .venv-functional/bin/python -c \
  'from optimizer.config import SimpleConfig; c=SimpleConfig.load("custom_sysbench.json"); c.validate(); print("CUSTOM_CONFIG: PASS")'
```

Run only on a dedicated bare-metal host:

```bash
source functional_example/site.env
sudo --preserve-env=SEMATUNE_SYSBENCH_HOST,SEMATUNE_SYSBENCH_PORT,SEMATUNE_SYSBENCH_USER,SEMATUNE_SYSBENCH_PASSWORD,SEMATUNE_SYSBENCH_DB \
  env PYTHONPATH="$PWD/src" "$PWD/.venv-functional/bin/python" \
  -m optimizer.main -c "$PWD/custom_sysbench.json"
```

| Field | Meaning |
| --- | --- |
| `benchmark` | Registered workload; `sysbench_oltp` selects PostgreSQL OLTP read/write. |
| `tuner_type` | Fixed, LLM, MLOS, Bayesian, DQN, or Q-learning. |
| `parameter_ranges` | Legal bounds or categorical values for exposed controls. |
| `parameters_to_tune` | Ordered controls visible to the tuner. |
| `fixed_parameters` | Values returned by Fixed; empty preserves observed values. |
| `optimization_metric` / `optimization_goal` | Objective and direction. |
| `max_iterations` / `post_tuning_windows` | Tuning and frozen measurement windows. |
| `window_duration` | Nominal seconds per optimizer window. |
| `respect_config_window_duration` | Prevents compatibility overrides of the duration. |
| `tuning_mode` / `continuous_apply` | Controls when and how often suggestions are requested. |
| `pin_to_cores` | Parameter/perf cores; OLTP itself currently uses CPUs 10–19. |
| `bind_network_irqs` | Allows or prevents NIC IRQ rebinding. |
| `sysbench_threads` | Worker threads. |
| `sysbench_tables` / `sysbench_table_size` | Prepared table count and rows per table. |
| `sysbench_rate` | Optional transaction-rate cap; `null` means unlimited. |
| `use_perf_stat` | Enables perf counters. |
| `results_dir` | Raw metrics and history destination. |

Database credentials come from `SEMATUNE_SYSBENCH_*`, generated by setup; do
not store them in JSON. LLM configs additionally need `GEMINI_API_KEY` or an
`llm_replay_file`.

The adapter selects scripts through
[`benchmark_registry.py`](../src/optimizer/benchmarks/benchmark_registry.py),
not the legacy `sysbench_script` field. Add a `BenchmarkType` entry to register
a genuinely new Lua script and its defaults/lifecycle requirements.
