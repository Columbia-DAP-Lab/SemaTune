# Artifact component and source map

## Artifact-level components and provenance

| Path | Component | Provenance |
| --- | --- | --- |
| `README.md`, `INSTRUCTIONS.md` | Reviewer workflows, expected resources, pass criteria, and output locations | TuxBot-authored evaluator documentation. |
| `src/optimizer/` | Optimization runtime, benchmark interface, Linux controls, memory, and tuners | TuxBot-authored implementation. |
| `functional_example/` | Reduced 14-method Sysbench Functional workflow, exact configs, committed diagnostic traces, and plotter | TuxBot-authored workflow; traces are derived from the documented real-provider Functional run and contain no credentials. |
| `reproduction/reproduce_claims.sh` | Unified base, `--extended`, and `--full` C1–C4 entry point | TuxBot-authored orchestration. |
| `reproduction/claim_manifest.json` | 21-configuration base claim selection | Derived from the paper experiment inventory and checked by `reproduction/suite.py`. |
| `reproduction/extended_claim_manifest.json` | 60-configuration, three-workload populated Plot 6/7/10 selection | Generated by `build_claim_tier_manifests.py`; no 4-knob or Trim/MLOS@41 job is selected. |
| `reproduction/full_claim_manifest.json` | 164-configuration, 11-workload Plot 6/7 selection plus three-workload Plot 10 | Generated by `build_claim_tier_manifests.py`; the command emits a multi-day/quota warning. |
| `reproduction/configs/` | Runnable configurations materialized from the archived experiments | Paper-derived configuration data; provider credentials are removed and output paths are redirected. |
| `reproduction/{suite.py,plot_claims.py,plot_three_app_paper.py,plot_c4_methods.py}` | Preflight, strict completion, resume, aggregation, fresh plots, and reports | TuxBot-authored reproduction and validation code. |
| `reproduction/trace_baselines/c1_c4_provider/` | Provider-free base fallback with per-response traces, checksums, claim report, and factors | Derived from the completed real-provider base run; replay reruns workloads and makes no provider calls. |
| `all_results/paper_evaluation/` | Curated paper-era optimization histories used by the archived plot validators | Measured experiment data; exact file coverage and SHA-256 values are recorded under `artifact/`. |
| `paper_evaluation_plots/` | Submitted reference PDFs and parameter-latency CSV | Accepted-paper output retained for visual and numerical comparison. |
| `scripts/artifact_plots/` | Paper Plot 6–12 wrappers and numerical validators | TuxBot-authored plotting orchestration over the curated histories. |
| `scripts/setup*.sh`, `scripts/fetch_artifact_inputs.py` | Base/full setup and digest-verified external input retrieval | TuxBot-authored automation; package/download inputs are locked under `artifact/`. |
| `config/benchbase/postgres/` | Retained BenchBase XML workload inputs | Experiment inputs used by the implemented BenchBase adapters. |
| `artifact/` | Environment description, package/download locks, checksums, claim map, and third-party modification record | Machine-readable and human-readable provenance metadata. |
| `deps/` | BenchBase, TailBench, DCPerf, and Mutilate submodules | Pinned third-party revisions; authorship and modifications are documented separately. |
| `tests/` | Functional, setup, manifest, trace-replay, and reproduction regression checks | TuxBot-authored verification code. |
| `tools/maintenance/` | Deterministic config/manifest derivation and trace-extraction helpers | Maintainer-only TuxBot utilities; not required by evaluator commands. |
| `requirements*.{in,txt,lock}` | Python inputs and locked dependency sets | Generated from the declared dependency inputs; hashes are retained where supported. |

Generated evaluator outputs belong under `results/` and are intentionally not
part of the artifact. Site-specific environment files, virtual environments,
download caches, logs, and build products are also excluded. The exact
third-party boundary is in
[`artifact/THIRD_PARTY_MODIFICATIONS.md`](../artifact/THIRD_PARTY_MODIFICATIONS.md),
and archived data coverage is in
[`artifact/paper_plot_inputs.json`](../artifact/paper_plot_inputs.json).

## Optimization runtime

The root modules in `src/optimizer/` implement the shared optimization runtime:

| File | Purpose |
| --- | --- |
| `__init__.py` | Marks the Python package and records its version. |
| `benchmark.py` | Defines the benchmark interface, metrics, and process helpers. |
| `config.py` | Loads and validates experiment configurations. |
| `main.py` | Runs single-loop experiments. |
| `dual_loop_main.py` | Runs Actor-Speculator experiments. |
| `optimizer.py` | Implements the single-loop measure, suggest, apply, and record lifecycle. |
| `dual_loop_optimizer.py` | Implements concurrent Actor/Speculator requests, application, stable evaluation, and history recording. |
| `main_helpers.py` | Constructs tuner implementations without circular imports. |
| `model_versions.py` | Centralizes hosted-model identifiers and settings. |
| `parameter_manager.py` | Validates, applies, reads, and restores Linux controls. |
| `token_bookkeeping.py` | Aggregates LLM token usage by role and phase. |

## Benchmark adapters

`src/optimizer/benchmarks/` adapts workloads to the shared interface:

| File | Purpose |
| --- | --- |
| `benchmark_registry.py` | Registers benchmark types, scripts, defaults, and lifecycle requirements. |
| `benchbase.py` | Runs BenchBase TPC-C, Wikipedia, Twitter, YCSB, and SIbench. |
| `sysbench.py` | Runs Sysbench OLTP, CPU, memory, FileIO, and threads. |
| `tailbench.py` | Runs the retained TailBench applications. |
| `dcperf.py` | Runs DCPerf SparkBench. |
| `mutilate_benchmark.py` | Coordinates Memcached and the remote load generator. |
| `mutilate_client.py` | Runs on the remote Mutilate load-generator node. |
| `mutilate_protocol.py` | Implements buffered, framed coordination messages. |
| `ADD_BENCHMARK_README.md` | Explains how to register another adapter. |
| `MUTILATE_README.md` | Documents distributed Mutilate execution. |
| `MUTILATE_INTERNAL_NETWORK_SETUP.md` | Documents the two-node network layout. |

## Cross-run memory

`src/optimizer/memory/` implements the agentic memory path:

| File | Purpose |
| --- | --- |
| `common.py` | Shared schemas, sanitization, aggregation, and formatting. |
| `redaction.py` | Produces sanitized retrieval documents from histories. |
| `summary.py` | Summarizes redacted histories with the configured provider. |
| `store.py` | Embeds, stores, and queries memory documents with ChromaDB. |

## Tuners

`src/optimizer/tuners/` contains the parameter-selection strategies:

| File | Purpose |
| --- | --- |
| `base.py` | Tuner interface and response object. |
| `fixed.py` | Fixed control baseline. |
| `llm.py` | Gemini/OpenRouter or recorded-response LLM tuner. |
| `llm_trimming.py` | LLM-guided search-space trimming. |
| `bayesian.py` | SMAC3 Bayesian optimization. |
| `mlos_tuner.py` | MLOS `SmacOptimizer` baseline. |
| `dqn.py` | PyTorch Deep Q-Network tuner. |
| `qlearning.py` | Tabular Q-learning tuner. |

Third-party sources remain separate under `deps/`; see [`deps/README.md`](../deps/README.md).

## Maintainer utilities

`tools/maintenance/` contains provenance-preserving utilities used to derive
the reduced Functional Sysbench configurations and credential-free replay
traces. Evaluators do not need these utilities for the documented workflows.
